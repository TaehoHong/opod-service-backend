# 캐릭터 소셜 활동 온보딩 문서 작성 계획

## 독자와 목표

개발 경험은 있지만 OPOD의 저장소 구조와 캐릭터 모델을 모르는 개발자를 대상으로 한다.
문서를 읽은 뒤 기능의 동작을 설명하고, 설정·실행·저장 코드의 소유자를 찾고,
활동이 발생하지 않는 이유를 좁힐 수 있어야 한다.

산출물은 `docs/character-social-activity-onboarding.md`의 초안이다.
현재 작업 트리의 구현을 설명하며 배포 여부를 보증하지 않는다.
코드·테스트·DDL·DB·배포 설정은 변경하지 않는다.

## 목차와 설명 방식

| 목차                      | 독자가 답할 질문                         | 설명 방식                                                |
| ------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| 1. 기능과 범위            | 누가 무엇을 자동으로 하는가?             | 사람 사용자와 캐릭터를 구분하고 조회의 의미를 먼저 정의  |
| 2. 한 번의 활동 예시      | 실제로 어떤 결과가 생기는가?             | 한 캐릭터의 관심사·시간대·남은 한도를 따라가는 숫자 예시 |
| 3. 구성 요소와 실행 흐름  | 어떤 프로세스가 무엇을 맡는가?           | 저장소 역할 표와 작은 흐름도, 메서드에 대응하는 단계     |
| 4. 활동 규칙              | 어떤 게시물과 작성자를 선택하는가?       | 필터·확률·누적 조건·한도의 차이와 경계 사례              |
| 5. 글로벌 시간 처리       | '오늘'과 '활동 시간'은 누구 기준인가?    | 현지 시각과 절대 시점을 분리하고 자정·DST 예시           |
| 6. 데이터 모델            | 왜 이 테이블과 필드가 필요한가?          | 각 데이터가 없으면 생기는 문제를 설명; DDL은 정본 링크   |
| 7. 중복·실패·중지 처리    | 서버가 여러 개거나 죽으면 어떻게 되는가? | 잠금·lease를 정의한 뒤 상태 전이와 중지의 한계 설명      |
| 8. 설정과 활성화          | 설정은 어디에 저장하고 언제 적용되는가?  | API 입력 예시, 캐릭터 정책과 프로세스 환경변수 분리      |
| 9. 코드 읽기와 검증       | 어디부터 읽고 무엇으로 확인하는가?       | 책임별 탐색 순서와 기존 E2E 명령·시나리오                |
| 10. 문제 해결과 남은 범위 | 동작하지 않으면 어디부터 보는가?         | 증상별 확인 순서와 현재 제공하지 않는 기능               |

설명은 목적 → 구체적 예시 → 실제 규칙 → 코드 근거 순서로 전개한다.
용어는 첫 등장에 정의하고 DB 이름은 필요한 지점에서만 노출한다.
숫자는 예시·환경변수 기본값·캐릭터별 설정값을 구분한다.
정책은 목표 활동량이 아닌 상한임을 명시한다.
좋아요와 조회·팔로우의 공개 집계 반영 차이, 현재 구현과 배포 상태를 구분한다.
구현되지 않은 기능은 설계 의도로 포장하지 않는다.

직접 확인했다. 구현 소유권이나 검증 명령을 바꾸지 않아 가이드의 기존 항목은 유지한다.
이번 검증은 문서 검증이다. 이전 구현 단계의 테스트 통과를 이번 실행 결과로 표시하지 않는다.

## 완료 기록

- Sol 읽기 전용 검토: 중요한 사실 오류 없음. 범위 표기의 Markdown 취소선 문제와
  최초 활성화 후 비동기 실행 시점 설명을 수정했다.
- 부모 에이전트: 소스와 규칙·기본값 대조, 내부 링크 16개 존재 확인,
  워커 환경변수 8개·PUT 필드 8개 정합성 검사, JSON 예시 파싱 완료.
- 두 문서의 Prettier 검사와 `git diff --check` 통과.
- 문서만 추가했으므로 빌드·단위·E2E 테스트는 이번 작업에서 실행하지 않았다.
- Knowledge Delta (`repo-evidenced`): 기존 구현의 용어·실행 규칙·필드 필요성·코드 탐색 경로를
  신규 개발자용 초안으로 정리했다. 제품 정책이나 코드 소유권을 새로 정의하지 않았다.
- 검토 초점: 설명용 숫자가 기본 정책으로 오해되지 않는지, 최초 합류자가 코드 읽기 순서와
  문제 해결 표만으로 조사 시작점을 찾을 수 있는지. 이 문서는 온보딩 초안이며 배포 증명이 아니다.
