# OPOD 약관·개인정보 동의 정책

범위: 약관·개인정보 문서 관리, 가입 시 동의 수집, 동의 기록과 변경.
상세 HTTP 계약은 docs/api/terms.md를 따른다.

## 핵심 결정

| 항목 | 정책 |
|---|---|
| 동의 항목 | 필수 3종(이용약관, 개인정보 수집·이용, 만 14세 이상)과 선택 1종(광고성 정보 수신)을 사용한다. |
| 문서 관리 | 유형·버전별 문서를 DB에 보관하고 시행일이 지난 최신 버전을 현재 버전으로 노출한다. |
| 수집 시점 | 회원가입 요청에서 필수 동의를 모두 받는다. |
| 증빙 버전 | 서버가 시행 중인 버전을 스탬프한다. 클라이언트는 버전을 보내지 않는다. |
| 기록 방식 | append-only로 남기며 유형별 최신 행이 현재 상태다. |
| 재동의 | 개정 시 미동의 상태를 알려주기만 하고 다른 API를 차단하지 않는다. |
| 증빙 항목 | 접속 IP와 User-Agent는 저장하지 않는다. |
| 탈퇴 | 동의 기록은 삭제하지 않고 익명화된 users 행에 남긴다. |

## 동의 항목

- 필수: `terms_of_service`, `privacy`, `age_14`. 미동의로는 가입할 수 없고
  가입 후에도 철회할 수 없다. 철회는 회원탈퇴로만 가능하다.
- 선택: `marketing`. 언제든 동의·철회할 수 있고 미동의도 정상 상태다.
- 필수와 선택 구분은 코드 상수이며 문서 데이터에 저장하지 않는다.

## 문서 관리

- 문서는 유형과 버전의 조합으로 유일하다.
- 유형별로 시행일(`effectiveAt`)이 현재보다 이전인 것 중 가장 최근 버전이
  현재 버전이다. 시행일이 미래인 문서는 노출하지도, 동의를 받지도 않는다.
- 작성·수정·발행은 opod-admin이 담당한다. 서비스는 조회만 한다.
- 시행 중인 문서가 없는 유형은 요구하지 않는다. 따라서 문서를 한 건도
  등록하지 않은 상태에서도 가입은 동작한다.

## 동의 수집과 기록

- 가입 요청은 시행 중인 필수 문서 전부에 동의해야 통과한다. 하나라도
  빠지면 400이며 계정도 동의 기록도 만들지 않는다.
- 계정 생성과 동의 기록은 한 트랜잭션에서 처리한다.
- 동의 기록은 수정하거나 삭제하지 않는다. 변경은 새 행을 덧붙이는 방식이며
  유형별 최신 행이 현재 상태다.
- 같은 버전에 같은 응답을 다시 보내면 기록을 늘리지 않는다.
- 저장 항목은 사용자, 유형, 버전, 동의 여부, 시각뿐이다. 개인정보 최소수집
  원칙에 따라 IP와 User-Agent는 남기지 않는다.

## 재동의

- 필수 항목의 현재 버전과 동의한 버전이 다르면 재동의가 필요한 상태로
  표시한다.
- 재동의를 강제하는 전역 게이트는 두지 않는다. 클라이언트가 동의 현황을
  조회해 배너나 모달로 유도한다.
- 선택 항목은 미동의도 정상 상태이므로 재동의 필요로 표시하지 않는다.
  버전 차이는 응답의 동의 버전과 현재 버전으로 판단할 수 있다.

## 탈퇴

- 동의 기록은 증빙이므로 탈퇴해도 삭제하지 않는다. users 행이 익명 상태로
  유지되므로 기록도 익명 상태로 남는다.
- 재가입은 새 계정이므로 동의를 다시 받는다.

## 저장소 경계

| 기능 | opod-service-backend | opod-admin |
|---|---|---|
| 약관 문서 | schema와 공개 조회 | 작성·수정·발행 |
| 동의 수집·기록 | 전체 동작 | 동의 이력 조회 |

## 알려진 제한

문서 작성 API가 아직 opod-admin에 없다. 그때까지 초기 문서 등록은 SQL로
처리한다 (docs/api/terms.md의 등록 예시 참조).
